Verified manually: opened the hamburger menu, then attempted to click the account-menu button - Playwright's own actionability check confirmed the hamburger's modal backdrop covers the account-menu button while open (a real user's click there would land on the backdrop, dismissing the hamburger, not opening the account menu on that same click); Escape reliably dismissed the hamburger; the account menu then opened normally on its own subsequent click.   **Revised from the original plan**: implementation revealed the shared `DropdownMenu` primitive renders a full-page modal backdrop while any menu is open, which blocks all other clicks (including on the other menu's trigger) until the open menu is dismissed - standard behavior for this component and for dropdown menus generally (Radix, Base UI, native `<select>`, etc. all work this way). True simultaneous-independence (both open at once, or a single click dismissing one and opening the other) is not achievable without reworking both dropdowns to be non-modal, diverging from how `DropdownMenu` is used everywhere else in the app. Per user decision, accepted standard one-at-a-time behavior instead; `proposal.md` and the `navigation/app-menu` delta spec were updated to describe this realistic behavior before continuing.
